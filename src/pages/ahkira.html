The GPU stayed home

I wanted a chat box on this site that answers questions about my work. I had the hardware to run it myself. The hard part was deciding not to.

ahkira is the little helper that will live on this site. Before any code got written it got three rules: it can't put my home network at risk, it can't go rogue and start sharing things it shouldn't, and when a recruiter shows up it has to work. Order mattered too. Plumbing and guard rails first. The mascot and the name last.

The first plan: run it on my own card

The obvious move was my gaming PC. RTX 3080, 12 GB, and I had just benchmarked it. A 30-billion-parameter mixture-of-experts model did about 43 tokens a second with only half of it on the card. A 14B model did about 72. Plenty for a chat. So the plan was simple: model on my PC, a tunnel from the website to it, no hosting bill.

Why I didn't

Speed was never the problem. The tunnel was.

  • It opens the house. A public endpoint that ends at my PC is a live path from the internet onto my home network. That same machine holds my personal files and has remote access on.
  • It ties the site to my home. Anything that links a public page to where I live is a real risk, not a theory.
  • It isn't always on. That PC sleeps, reboots and plays games. A recruiter would hit a dead box.
  • Abuse lands on my power bill. Every bad actor would be burning my GPU, with nothing in front to slow them down.

My other GPU box was worse. It runs the house's voice assistant and sits next to the backups. So instead of promising to be careful, I made the home risk zero by design: nothing in my house is reachable from this site. At all.

What runs instead

Your question goes to a small server at the edge of the internet, running an open-source model there. My home network isn't part of it.

  • The page works without the model. Eleven questions have answers I wrote and checked myself, and they work with JavaScript off. Only a question you type goes to the server. If the server is down, ahkira is napping. That's a designed state, not an error.
  • Nothing private to leak. The model only ever sees the public pages of this site, after a filter strips anything sensitive. No fine-tuning, no private notes, nothing personal in its context. This is the rule that actually keeps me safe.
  • Guards in front. A bot check, per-visitor and daily limits, short questions, short answers, a hidden tripwire for anyone fishing for its instructions, a reply checker, and an off switch.
  • Chats are saved. Emails and phone numbers get blanked before anything is stored, and saved chats never go back into what it reads.

Trying to break it

This is where the 3080 earned its spot after all. It became the lab. Same server code, run locally against the same family of model, fake secrets planted as bait, and scripted attacks thrown at it: jailbreaks, prompt extraction, leak attempts, plain abuse.

Then two frontier AI models took turns playing attacker, two rounds each. Every trick that worked got fixed and became a permanent test. The suite is now 81 attack cases with zero failures, plus 70 unit tests.

The most useful lesson was the uncomfortable one. Round two showed the reply checker is basically a word list: it rephrased its way past 56 of 62 variations. So the checker is a seatbelt, not the wall. The wall is that there's nothing private in the model's context to begin with. That's why my claim is "this many attacks, zero leaks," and never "it can't be tricked."

Small things that bit me

  • The hosted model "thinks" by default. It burned its whole answer budget reasoning and came back empty until I turned that off.
  • It copied an example sentence out of its own persona word for word and tripped the echo guard. Persona instructions don't include copyable sentences anymore.
  • The bot check fails in a headless browser, so the end-to-end tests run in a visible one.

Where it stands

ahkira is running privately on the real setup. Every refusal path has been checked and every live test turn has passed. Public launch is next. Everything after that is on the Coming soon tab.
