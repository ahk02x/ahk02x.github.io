It has to fit

By Amir Khademi

I wanted to know what normal hardware can actually do with free, open AI models. Not a datacenter, not a spec sheet. The stuff already in my house. The answer turned out to be one word, and it isn't "speed".

After I decided the GPU stays home, my gaming PC's RTX 3080 became the lab. A lab needs a ruler, so I built one: a small script that sends the same prompts to the same models on any machine and writes down everything. Then I ran it on the three machines I had. The 3080 with 12 GB of video memory, an older RTX 2070 SUPER with 8 GB in my home server, and my laptop, an Apple M3 with 16 GB.

How I measured

Same prompts every time, randomness turned off (temperature 0, fixed seed), and a cap of 200 tokens per answer. A token is a chunk of text, about three-quarters of a word. The headline number is tokens per second: how fast the model writes once it starts. Above about 10, it's writing faster than you can read.

  • Load time is kept separate. The first call loads the model from disk and is slow. It never gets mixed into the speed number.
  • Three runs, take the middle one. The spread between runs was tiny, under 3% on the first card.
  • Eight small tasks, graded by code. Pull fields out of a message, a couple of word problems, convert a date, find one fact hidden in a long block of text. Graded by a script, not by another AI. It's a sanity check, not an IQ test.
  • Record how much landed on the GPU. If a model doesn't fit in the GPU's memory, the rest quietly goes to normal RAM and the CPU runs that part. The runtime reports the split, so every row says what share was on the GPU. That one column ended up explaining almost everything.

I also threw out a number. The prompt-reading speed in my first table came out at 70,000 to 180,000 tokens a second, which is nonsense. I was sending the same prompt again and again, and the runtime was clearly reusing work, so that column measured the cache, not the card. It's gone from the report. A number I can't back up doesn't get rounded into something nicer.

The cliff

Take one 14-billion-parameter model and store it at different precisions. Fewer bits per number makes it smaller. On the 3080:

  • 4-bit, 9.5 GB, all on the GPU: 71.7 tokens a second.
  • 6-bit, 13.1 GB, 80% on the GPU: 14.1.
  • 8-bit, 16.7 GB, 63% on the GPU: 6.2.

Not a slope, a cliff. The moment a fifth of the model spills off the card, it runs at a fifth of the speed. Long conversations cause the same cliff. The model keeps a working memory of the conversation, and that memory grows as the conversation does. The same 4-bit model went from 66 tokens a second with room for about 8,000 tokens of text to 18 at 16,000 and under 4 at 32,000, as the conversation pushed it off the card.

The cheat code

A mixture-of-experts model is split into many small "expert" parts, and only a few run for each token. I tried a 30B one that only uses about 3B per token, next to a normal 32B. Both were too big for 12 GB, and both had about half of themselves spilled into RAM.

The normal 32B ran at 3.1 tokens a second. The mixture-of-experts one ran at 42.6. Same card, same spill, almost 14 times faster. If you have a small card, this is the kind of model to look at first. (The two models also differ in other ways, so I can't pin the whole gap on that one design choice. But it's the obvious suspect.)

My laptop beat a GPU

This is the one I didn't expect. The same 14B 4-bit model, on all three machines:

RTX 308012 GB on the card100%71.7
Apple M3 laptop16 GB shared by CPU and GPU100%8.0
RTX 2070 SUPER8 GB on the card64%0.7

The laptop ran it 11.4 times faster than a real graphics card. Not because the M3 is fast. Its memory is shared, so the whole 9.5 GB model fit in one place. On the 8 GB card a third of it spilled, and 0.7 tokens a second is one word every two seconds or so.

Flip it around and the GPUs win easily. On 7B models that fit everywhere, the 2070 SUPER was 4 times faster than the laptop and the 3080 was 7.6 times faster. Once a model fits, memory speed seems to set the pace: the 3080's published memory bandwidth is about twice the 2070 SUPER's, and it ran the same 7B model 1.87 times faster.

So: memory size decides whether you can run a model at all. Memory speed decides how fast, once it fits.

What it doesn't say

These are three different machines, not one controlled experiment. They differ in CPU, software version and what else was running. The home server card runs in a container with a 4-core, 8 GB limit and was sharing a bit of its memory with another job. My laptop was in light use. Everything came from one session per machine. And eight tasks are far too few to say which model is smarter. The full technical report puts every one of these caveats next to the number it affects. It's public: the report and the raw data and the script are on GitHub.

What's next

  • Make it repeatable. Save every call's timing and the exact model file, use one runtime version everywhere, and rerun on different days.
  • Power. Run the 3080 at 250, 320 and 390 W and measure energy per token. My guess is it barely slows down at 250. (And no, this won't kill the card. Inference is way gentler than gaming.)
  • Squeeze the memory. Store the conversation memory at 8 bits instead of 16 and see how far that pushes the cliff.
  • Biggest model that's still usable. Pick a bar, say 10 tokens a second, and find the largest model each machine clears. That's the chart most people actually want.
  • Real work, not puzzles. Run my own kinds of tasks on these models and see what share could stay on a home card.

The question underneath all of it: if 12 GB is the wall, what happens with a lot more memory? A machine with 128 GB of unified memory would answer that directly. For now, the rule is simple. Before you ask how fast, ask whether it fits.
