AI models on my own hardware

By Amir Khademi

I wanted to know what free, open AI models can do on the machines already in my house. What mattered most wasn't speed. It was whether the model fits in memory.

After I decided the site's chat box wouldn't run in my house, my gaming PC's RTX 3080 became my test machine. I had AI write a small script that sends the same prompts to the same models on any machine and records everything. Then I ran it on the three machines I had: the 3080 with 12 GB of video memory, an older RTX 2070 SUPER with 8 GB in my home server, and my laptop, an Apple M3 with 16 GB.

How I measured

Same prompts every time, randomness turned off (temperature 0, fixed seed), and a cap of 200 tokens per answer. A token is a chunk of text, about three-quarters of a word. The main number is tokens per second: how fast the model writes once it starts. Above about 10, it's writing faster than you can read.

  • Load time is kept separate. The first call loads the model from disk and is slow. It never gets mixed into the speed number.
  • Three runs, take the middle one. On the 3080 the runs were within 3% of each other.
  • Eight small tasks, graded by code. Pull fields out of a message, a couple of word problems, convert a date, find one fact hidden in a long block of text. Graded by a script, not by another AI. It only catches basic mistakes. It doesn't say which model is smarter.
  • Record how much landed on the GPU. If a model doesn't fit in the GPU's memory, the rest goes to normal RAM and the CPU runs that part. The runtime reports the split, so every row says what share was on the GPU. That one column explained almost everything.

I also threw out a number. Prompt-reading speed in my first table came out at 70,000 to 180,000 tokens a second, which is impossible. I was sending the same prompt again and again and the runtime was reusing its work, so that column measured the cache, not the card. It's gone from the report.

Speed drops fast once a model spills

Take one 14-billion-parameter model and store it at different precisions. Fewer bits per number makes it smaller. On the 3080:

Same 14B model on the RTX 3080 (12 GB) at three precisions
PrecisionSizeOn the GPUTokens/s
4-bit9.5 GB100%71.7
6-bit13.1 GB80%14.1
8-bit16.7 GB63%6.2

When a fifth of the model spilled off the card, it ran at a fifth of the speed. Long conversations do the same thing. The model keeps a working memory of the conversation, and it grows as the conversation does. With room for about 8,000 tokens of conversation, the same 4-bit model ran at 66 tokens a second. At 16,000 it dropped to 18. At 32,000 it was under 4, because that memory pushed the model off the card.

Mixture-of-experts models

A mixture-of-experts model is split into many small "expert" parts, and only a few run for each token. I tried a 30B one that only uses about 3B per token, next to a normal 32B. Both were too big for 12 GB, and both had about half of themselves spilled into RAM.

The normal 32B ran at 3.1 tokens a second. The mixture-of-experts one ran at 42.6. Same card, same spill, almost 14 times faster. If you have a small card, this is the kind of model to try first. The two models also differ in other ways, so I can't put the whole gap on that one design choice, but it's the likely reason.

The laptop beat the older GPU

I didn't expect this one. The same 14B 4-bit model, on all three machines:

Same 14B 4-bit model, tokens per second, and how much of it sat in GPU memory
MachineMemoryOn the GPUTokens/s
RTX 308012 GB on the card100%71.7
Apple M3 laptop16 GB shared by CPU and GPU100%8.0
RTX 2070 SUPER8 GB on the card64%0.7

The laptop ran it 11.4 times faster than the 2070 SUPER. The M3 isn't fast. Its memory is shared, so the whole 9.5 GB model fit in one place. On the 8 GB card a third of it spilled, and 0.7 tokens a second is about one word every two seconds.

When the model fits everywhere, the GPUs win easily. On 7B models, the 2070 SUPER was 4 times faster than the laptop and the 3080 was 7.6 times faster. Once a model fits, memory speed seems to set the pace: the 3080's published memory bandwidth is about twice the 2070 SUPER's, and it ran the same 7B model 1.87 times faster.

So memory size decides whether a model runs at a usable speed, and memory speed seems to decide how fast it runs once it fits.

What it doesn't say

These are three different machines, not one controlled experiment. They differ in CPU, software version and what else was running. The home server card runs in a container with a 4-core, 8 GB limit and was sharing some of its memory with another job. My laptop was in light use. Everything came from one session per machine, and eight tasks are far too few to say which model is smarter. The full report puts each caveat next to the number it affects. It's public: the report, and the raw data and the script, are on GitHub.

What's next

  • Make it repeatable. Save every call's timing and the exact model file, use one runtime version everywhere, and rerun on different days.
  • Power. Run the 3080 at 250, 320 and 390 W and measure energy per token. My guess is it barely slows down at 250. (This won't hurt the card. Inference is much gentler than gaming.)
  • Smaller conversation memory. Store it at 8 bits instead of 16 and see how much longer a conversation can get before the speed drops.
  • Biggest model that's still usable. Pick a bar, say 10 tokens a second, and find the largest model each machine clears.
  • Real work, not puzzles. Run my own kinds of tasks on these models and see how many a home card could handle.

The open question: if 12 GB is the limit, what happens with a lot more memory? A machine with 128 GB of unified memory would answer that directly.
