The wall stays red until I say so

By Amir Khademi

There is a Dell U2719D turned on its side on my wall, driven by the monitoring box, on 24/7. It is the alarm surface for my home fleet. When something breaks it goes red, and it stays red until a person clears it on purpose.

Every other alert channel I have is something I choose to check. A phone notification, a toast on the TV, a key on a Stream Deck: each one waits for me to look. A wall does not. You walk past it from the hallway and the state of the fleet is in your eye whether you asked or not.

The display is called PHOSPHOR: one HTML5 canvas page in a Chromium kiosk, drawn like an 80s-movie control panel, thirteen panels in phosphor green. The reference look is eye candy; here every panel means something. A 17-button service matrix is one button per fleet check. The link panel is real throughput on a log scale with a 1 kb/s floor, because on a linear scale a home connection is a flat line. There are no fake numbers on the glass.

Two decisions I don't re-litigate

  • Every alarm wakes it. There is no severity threshold. The watchdog on the monitoring box latches on anything, drives the monitor's power line on, and the wall draws the reason. The escape hatch is a quiet-list file, one check name per line, re-read every tick. Nothing is silent by default.
  • It latches. The overlay stays up until I run phosphor ack, even after the condition has cleared. A blip at three in the morning is still on the glass at eight. An alert that tidies itself up is an alert you never found out about, and it hides the fact that nobody made a decision.

The alarm is an overlay, not a fourteenth panel: opaque, anchored to the top, covering three panels while it is up. A live critical is red and pulses, because motion is what catches an eye that is not already looking. A recovered alert is amber, titled RECOVERED · UNACKNOWLEDGED, with how long it has been held. If the feed behind it has gone stale, the footer says LAST KNOWN REASON, NOT CURRENT.

Never lie when the feed dies

A wall display that lies when its feed dies is worse than one that goes dark.

After 30 seconds without a successful read, every panel that asserts a fact degrades on purpose: the service buttons drop to dark outlines under an amber NO LINK · STATE UNKNOWN, the lamps go out, the channel strip flatlines, the log prints LAST VALUES · NOT TRUSTED. Ambience is still allowed; the waveform keeps drifting so the thing does not read as a broken TV. Synthetic motion is fine. Synthetic motion presented as a measurement is not.

The version of "dead" that took longest to see was the one where the transport is fine: HTTP returns 200, the JSON is well formed, and the data stopped moving hours ago. Freeze the process that writes the fleet status file and the matrix would happily light 17 green buttons under a cheerful FEED OK 0s. The fix was to make every data source return its own source timestamp beside its payload, with a per-source maximum age (180 seconds for the fleet file). The current time is forbidden as that timestamp: it is the time you ran, not the age of the data.

One lie the wall cannot catch is its own death. The box it runs on hard-locked twice in August and the wall was dark for three hours. A self-hosted alarm surface cannot report that, and a clean run since is not evidence it won't recur. Something else has to watch the watcher.

Don't render for an empty room

The HDMI hotplug line stays asserted when a monitor is in standby, so the operating system cannot tell the screen is off and renders happily for nobody. The side-channel that actually knows is DDC/CI: the monitor answers a power query over the display's I2C bus. The feed server polls it every 20 seconds, and the page parks its frame loop when the screen reports off. Measured: 39.5% of one core with the screen on, 0.7% off, and the chip runs 45 to 47 °C against 39 °C. Any DDC error or timeout leaves the state as on. A failed probe must never blank the wall.

That same DDC path is how an alarm wakes the screen, and it needs no network at all, so leaving the screen off overnight is safe. One wrinkle: the poller takes up to 20 seconds to notice the watchdog has driven the power on, and for that gap the wall would show a frozen last frame. So the feed forces rendering for a 45-second window after the watchdog asserts power. At first that was a state, and it left a screen I had physically switched off rendering a full canvas at about 37% of a core. A render-anyway override is a window, never a state.

Things that cost an afternoon

  • Check the glass, not the config. xrandr reported a perfect rotated 1440×2560 while Chromium sat in a corner at its default window size, because kiosk mode asks a window manager to go fullscreen and there was none to ask. Only a screenshot of the real screen showed it.
  • The canvas was never the bottleneck. Render cost started at 60% of a core. Dropping a mix-blend-mode from the scanline overlay and animating the roll band with transform instead of top bought more than all thirteen panels cost. Frame rate went from 20 to 12 because the feed only updates every 3 seconds.

Pages are a contract

The wall is n-way now; phosphor view puts any registered page on the glass. Adding a page means four new files and no edits to shared code, written down as a contract so that Claude Code agents can build a page without touching the shell. The shell paints the status band, the no-link banner and the alert overlay after the page draws, so a page cannot cover or omit them.

The screen draws about 20 W, roughly 175 kWh a year, on a box that is on anyway. Open items: a flash on a sound event, night dimming, and a macOS screensaver hosting the same page. What this taught me: the useful property of a display is not what it shows when everything works. It is what it refuses to pretend when something doesn't.
